## 3. Findings — actionable (deduped across inline + 10-dimension audit)

### 🟠 HIGH

**H1 · Wishlist renders the ENTIRE list as "Ekki í boði" when Woo is down or slow (>5s).**
`tier: code-read` · `src/pages/api/products.ts:23` + `WishlistView.tsx:57-63,139`
`getProductsByIds(ids).catch(() => [])` turns any Woo outage/timeout (the REST client uses
`AbortSignal.timeout(5000)`) into a **200 with body `[]`**. `WishlistView` checks only `res.ok` → sets
`fetchOk=true` → `gone = fetchOk && !c` becomes true for **every** saved item → all render the
"Ekki í boði / Ekki lengur fáanleg" non-link card. This defeats the component's own documented intent of
distinguishing *deleted* from *fetch-failed*. A merely slow Woo (>5s) trips the identical path. Live-proven
the route returns `200 []` for unresolved ids; the full Woo-down leg needs `WP_INTERNAL_URL` repointed to
confirm (out of scope on the shared dev box).
**Fix:** don't collapse backend-failure into the deleted signal — return a non-2xx on
`getProductsByIds` failure (so `WishlistView` falls back to stored fields), **or** echo back the ids the
route actually attempted so "absent" ≠ "never-fetched". The echo-attempted-ids fix also closes M3.

### 🟡 MEDIUM

**M1 · Variable PDP shows no price until a size is selected** — violates the "frá {min} everywhere"
invariant. `tier: verified-live` · `vara/[slug].astro:163-167` (price div gated `type !== 'variable'`) +
`ProductPurchase.tsx:141-148` (price only when `resolved`). The shop card, recently-viewed strip, and
JSON-LD all carry `frá {min} kr.` for the same product, but the PDP's `.pdp__info` shows nothing until a
swatch is clicked. A shopper sees a price in the shop, opens the product, and the price vanishes.
**Fix:** render the parent's `frá {min} kr.` as the default (the page already derives this min for
`recentPriceText` + JSON-LD `priceRange`), then let `ProductPurchase` replace it with the resolved
variation price on selection.

**M2 · Facet count badges overstate the real filtered result.** `tier: verified-live` ·
`ShopFilters.astro:116` (count from REST `listAttributeTerms`) vs grid from Store API `storeProducts`.
The badge count and the grid come from **different data sources**: `litur=svartur` badge **365** but
`/verslun?litur=svartur` returns **216** (40% over); on category pages it stays global — badge **365** on
`/verslun/aefingabunadur?litur=svartur` which actually returns **13** (28× over); and the badge never
narrows when another facet is already active. **Fix:** drop the per-option count (simplest, removes the
false promise) or derive counts from the same Store API request that builds the grid. Brand badges are fine.

**M3 · Wishlists over 100 items falsely show the oldest saves as deleted.** `tier: verified-live` ·
`api/products.ts:9,18` (`MAX_IDS=100`, `.slice(0,100)`) vs `WishlistView.tsx:54` (sends every id uncapped).
New saves `unshift` to the front, so positions 101+ are the **oldest** items; they get sliced off before
resolving and come back as "Ekki í boði". **Fix:** chunk/paginate the id requests, or echo attempted ids
(same fix as H1).

**M4 · `/leita` carries contradictory indexing signals.** `tier: verified-live` · in the **sitemap**
(`sitemap.xml.ts:7-16`) **and** `Disallow: /leita` in robots.txt **and** no `noindex` meta. The sitemap
invites the crawl, robots blocks it → Search Console "Submitted URL blocked by robots.txt". **Fix:** remove
`/leita` from `STATIC_PATHS`, then pick **one** suppression method (the robots Disallow is sufficient).

**M5 · Heading level skips h1→h3 on shop and every category listing (no h2).** `tier: verified-live` ·
`ProductCard.astro:33` (h3 title) with no intervening section h2 on `/verslun` or `/verslun/[category]`
(home is correct h1→h2→h3). WCAG 1.3.1. **Fix:** wrap the grid in `<section aria-labelledby>` with a
visually-hidden `<h2>` (e.g. "Vörur"), or demote card titles to a non-heading element.

**M6 · BACS thank-you receipt is lost on refresh/bookmark.** `tier: code-read+verified-live` ·
`CheckoutForm.tsx:172` redirects to `/utskra/takk?order=…` but `takk.astro:12-26` reads only `order_id` +
`order_key` (the `order` param is dead), so the bank-transfer receipt resolves **only** from the `mos_order`
httpOnly cookie — which `takk.astro:28` **clears one-shot on every view**. Refresh, bookmark, or share →
neutral copy, no order number, no bank-transfer instructions. **Fix:** redirect BACS to
`/utskra/takk?order_id=${data.order_id}&order_key=${encodeURIComponent(data.order_key)}` (the
`OrderResult` already carries `order_key`) so the URL is the source of truth.

### 🔵 LOW (11)

- **L1 · Checkout defaults the payment selection to the LIVE Straumur gateway** (`CheckoutForm.tsx:36-76`,
  `PAYMENT_ORDER=['straumur','bacs']`). Not a code defect — a **launch-checklist** item: gate Straumur
  behind a TEST key (or temporarily default to `bacs`) until the live-key go-live runbook runs.
- **L2 · Sitemap cold-fetch cost.** `tier: verified-live` · 10-min TTL is shorter than crawler re-fetch
  intervals, so nearly every real crawl pays a **~7.4s** cold Woo sweep (3155 URLs), with no
  stale-while-revalidate and no in-flight dedup; cache is lost on deploy. **Fix:** raise TTL to 6–24h +
  serve stale-while-revalidate + dedup concurrent cold requests. *(This is the 9.8s I first measured.)*
- **L3 · Hero collage and "Nýjustu vörurnar" grid render the identical first 3 products** (`index.astro:23`
  + `:119`). De-dupe: grid from `newest.items.slice(3, 11)`.
- **L4 · og:image / twitter:image missing on homepage + category pages** (only PDPs emit them) → weak
  social cards. Add a default branded 1200×630 OG image fallback in `Base.astro`.
  **→ DEFERRED (2026-06-04):** no branded 1200×630 asset exists in `public/` and none can be
  fabricated to launch quality; ship the asset later, then a ~3-line `Base.astro` fallback.
- **L5 · Size swatches render in unsorted (raw API term) order** — `46, 45, 41, 42, 42.5, 44, 44.5, 43.5`.
  `tier: verified-live+code-read` · `ProductPurchase.tsx:122` maps `a.options` directly,
  `[slug].astro:44` passes them unsorted. Natural-sort numeric sizes (handle `42.5`; use an order map for
  `S/M/L/XL`). *(My inline finding; not contradicted by the audit.)*
- **L6 · Sort `<select>` auto-submits on `onchange`** (`ShopFilters.astro:79`) — keyboard/no-JS friction
  (WCAG 3.2.2). Let the existing "Sía" button drive it.
- **L7 · Post-payment `redirect_url` followed without an origin allowlist** (`CheckoutForm.tsx:165-168`).
  Defense-in-depth: assert `https://` + known gateway host, else fall back to `/utskra/villa`.
- **L8 · Coupon error messages render in English** in an Icelandic-only UI (`CouponField.tsx:28`). Map known
  Store API coupon error codes to Icelandic.
- **L9 · Coupon/shipping/checkout error strings rendered with HTML entities un-decoded** (e.g. literal
  `&quot;`). Cosmetic; run server error messages through `decodeEntities` (item/rate names already are).
- **L10 · PDP thumbnail-click vs variation-select don't sync each other's aria/state**
  (`Base.astro:204-215` vs `ProductPurchase.tsx:67-87`) — minor aria desync of `#pdp-main`.
- **L11 · Base.astro thumbnail swap doesn't re-arm the one-shot `onerror` placeholder fallback**
  (`Base.astro:209-211`); `ProductPurchase` does. Cheap consistency fix.
- **L12 · Mobile facet option rows may clip** (`tier: could-not-fully-verify`) — at 390px the `.facet-opt`
  label+badge extends ~60px past the viewport inside the (overflow-contained) filter panel; no broken page
