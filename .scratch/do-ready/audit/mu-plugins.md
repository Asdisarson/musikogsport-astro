## Checks that found nothing (so they are not re-opened)

- Permission callbacks: all `mos/v1` routes are `__return_true` by design (public reads, contact, password reset) except `account/logout`
  (`is_user_logged_in`, Bearer). No route writes product data. No nonce is needed (no cookie-authenticated state change).
- SQL: only `mos-size-index.php` uses `$wpdb`; ids are ints, taxonomy names `esc_sql`, `prepare` used for the one dynamic value. Matches the
  earlier ship verdict.
- Output escaping: all REST output is JSON; `title`/`name` fields pass `mos_plain_text`; `shipping_bar` messages `wp_kses_post`; `price_html` is
  sanitised again in the storefront (`PriceTag.astro:13`); other ACF text is escaped by Astro/React on render.
- Product data is never modified: the only writes are `mos_size` terms/relationships, `mos_contact` posts, transients, `mos_jwt_rehash` user
  meta and (via the checkout hook) order meta `_billing_ssn` / `skiptimidi`.
- Hook priorities with WooCommerce: `woocommerce_api_straumur` at 1 (before the gateway), `wp_redirect` filter gated on the flag set there (not `$_GET`),
  `woocommerce_get_return_url` 10, `template_redirect` 1 and 5 (before Woo's 10 and before `WC_AJAX::do_wc_ajax` at 0 exits for wc-ajax),
  `wc_product_post_type_link_product_cat` 20, Store API filters 10/11, `determine_current_user` 99 after the JWT plugin (10), size-index flush at
  `shutdown` PHP_INT_MAX after `fastcgi_finish_request`. The stock-reduction path is only observed, never altered.
- PHP 8.x: `php -l` clean on PHP 8.5.10; `strict_types` on every plugin; no dynamic properties, no `${}` interpolation.
- CORS/cookies: no mu-plugin sets CORS or cookies. WordPress core reflects any `Origin` with `Allow-Credentials: true` on REST (probed with
  `Origin: https://evil.example`), but cookie auth needs `X-WP-Nonce`, and the storefront calls WP server-side with Bearer/Basic, so no impact.

## End-to-end path notes

1. **Payment return (Straumur).** Storefront posts the order; the gateway's `redirect_url` goes to Straumur; the shopper returns to
   `WP_HOME/?wc-api=straumur&straumur_nonce=&order_id=&checkoutReference=`. `woocommerce_api_straumur` (priority 1) sets
   `mos_in_straumur_return`; the gateway's `process_return` (lines 472-545 of the plugin) issues `wp_safe_redirect`; `wp_redirect` filter in
   `headless-bridge.php:92-120` either passes the storefront outcome URL (key removed) or forces `/gera-upp/?straumurStatus=failed[&order_id=n]`;
   the WP-host URL is then forwarded by `mos-headless-mode.php` (priority 5) to the storefront with the query intact. The success URL comes from
   `woocommerce_get_return_url` (priority 10), which applies to every gateway (bacs/cod too), which is intended. Gaps: nonce failure (MU-09),
   `custom_success_url` set (MU-09), and the local shim (MU-01).
2. **Sign-in / reset / sign-out.** Storefront `login` -> `jwt-auth/v1/token` (token carries `data.mos_pwh`, added by the `jwt_auth_token_before_sign` filter);
   every Bearer request passes `determine_current_user` at 99 (signature, denylist, fingerprint); logout denylists `header.payload`; lost/reset password
   use WooCommerce's reset email and `reset_password()`, which fires `wp_set_password` and so invalidates older tokens. Gaps: MU-02, MU-05, MU-06, MU-21.
3. **Checkout fields.** `extensions.mos` -> `woocommerce_store_api_checkout_update_order_from_request` -> order meta; invalid kennitala is a 400 via
   `RouteException`. Gap: MU-03 (retry keeps stale values). Kennitala is stored as plain `_billing_ssn`, hidden (underscore) in admin, with no checksum
   check (length only).
4. **Catalog filters.** `mos_and_cat` / `mos_size` globals are set in `rest_request_before_callbacks`, applied in `pre_get_posts`, folded into Woo's
   count cache via `woocommerce_pre_product_filter_data`. Verified by the six tests. Gaps: MU-15, MU-16.
5. **Headless redirects.** `/verslun/...` -> 302 (301 once `MOS_HEADLESS_REDIRECT_STATUS` is set) to `MOS_STOREFRONT_URL` + the same URI; no open
   redirect found (MU-19); `MOS_STOREFRONT_URL` unset -> no-op (so with both constants unset, bridge-driven returns stay on WP; DEPLOY covers this).
