## End-to-end path notes (components' part)

- Browse -> filter: ArchiveView links are plain GETs; JS fetches the same URL (15 s timeout, abort on superseding clicks, `generation` guard for load-more, any failure falls back to real navigation). `popstate` and bfcache handled. Cards add to cart via the delegated script in ProductCard (survives swaps).
- Product -> cart: ProductPurchase resolves the variation client-side (`resolveVariation`), sends the variation id plus attribute values; failure shows inline (CO-08 a11y); success opens the drawer. Drawer/CartView/Checkout all read the `cart` store; the store is the only client-side copy and is refreshed only on load or after own writes (CO-05).
- Cart load: unconditional `GET /api/cart` per page view (CO-02) and no failure state (CO-01).
- Checkout: fields -> `setCustomer` re-quote (600 ms debounce, only when postcode/address/city change) -> postbox picker (CO-03) -> `Panta` -> `/api/checkout` under `withCartLock` (45 s client timeout vs 25 s server backstop, LM-01/LM-02) -> redirect target validated by `paymentRedirectTarget` (LM-13 sound) -> bfcache return (CO-04).
- Wishlist: hearts exist only on the PDP, write localStorage + `mos:wishlist`; header count and WishlistView listen (storage + custom event); the view revalidates ids through `/api/products` (capped at WISHLIST_MAX_IDS) with "gone" detection (CO-11, CO-16). The server never knows the list, so there is nothing to desync with except `localStorage` itself.
- Contact: JS path posts JSON to `/api/contact`, no-JS path posts the form and reads `?sent/?error` (CO-11).
- Sign-in: popup/page forms post natively to `/api/account/login`; header label flips to "Mín síða" from the non-secret `mos_li` cookie (CO-17).
